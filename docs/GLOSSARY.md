## 7. Правила перевода host-строк

1. Это **инструкции агенту**: важнее точность смысла, предупреждений и границ
   («только чтение», «нужно подтверждение пользователя», «не выполняйте») чем
   дословность. Сокращать предупреждения и оговорки нельзя.
2. Markdown сохраняется: `**жирный**`, backticks, списки, заголовки `#`, цитаты `>`,
   переносы строк и завершающие пробелы фрагментов (они склеивают текст с
   подставляемыми значениями).
3. Числа, диапазоны, единицы и значения по умолчанию переносятся без изменений:
   `1~500`, `0~2^53-1`, `≤512`, `4000`, `256KB`, `1MB`, `10~1800 секунд`.
   Диапазон записывается той же тильдой `~`, а не «—».
4. Плейсхолдеры (`{count}`, `{name}`, `${...}`) не переводятся и не переставляются.
5. Счётные конструкции — нейтральные: «сколько записей максимум вернуть», «число
   строк», «элементов»; никаких склонений по числу, которое подставляется в рантайме.
6. Строки, собираемые в рантайме (`plugin:dsh-rss-digest`, `plugin:dsh-tty:terminals`),
   переводятся фрагментами: фрагмент подставляется только там, где встречается ровно
   один раз, поэтому каждый фрагмент должен читаться в своём окружении (обычно это
   продолжение фразы после подставленного числа или имени).
7. Хэши в `src/host/ru/*.json` копируются из `catalogs/host/*.json` дословно: это
   единственный признак того, что исходная строка не изменилась. Расхождение = запись
   пропускается с предупреждением, исходный текст плагина остаётся.

## 8. Известные ограничения

- `plugin:dsh-rss-digest`, хвостовая строка «(всего N материалов, показаны первые M;
  полностью — в …)» закрывается полноширинной скобкой `）`: она статический литерал
  вне фрагментов и остаётся китайской пунктуацией. Косметика, правится только на
  стороне плагина; на смысл не влияет.
- `plugin:dsh-codegraph:usage` — английский текст, собираемый в рантайме, китайских
  литералов в нём нет, поэтому он не переводится (в `catalogs/host/prompt.json`
  помечен `translatable: false`).
- `tunnel_start` / `tunnel_stop` генерируются плагином в цикле; их описания попали в
  снимок после доработки извлекателя (`src/host/scripts/extract.mjs`), хэши взяты из
  каталога.
- Динамические фрагменты с хэшем не применяются, если плагин переформулировал текст:
  это осознанное поведение (лучше оригинал, чем устаревший перевод).
- Динамические фрагменты подставляются **во все свои вхождения** атомарно
  (`src/host/index.ts`): у каждого фрагмента в каталоге есть `count` — сколько раз он
  встречается в снимке. Если в живом тексте число вхождений другое, фрагмент не
  применяется (предупреждение), чтобы не перевести половину; вхождения внутри уже
  переведённого более длинного литерала пропускаются. Так `plugin:dsh-tty:terminals`
  корректно переводится и при нескольких сессиях (`[运行中…]`, `(最后活动`,
  `退出码未知`), и когда одновременно есть завершённые сессии и скрытые вкладки
  (`另有` дважды).

Правила для ядровых словарей:

1. **Порядок ключей — как в owner-словаре Harness**: гейт
   `check:harness:keys` сравнивает базовые ключи позиционно. Файлы
   генерируются в порядке owner-объекта; вручную вставлять ключи «куда удобно»
   нельзя.
2. **Плюральные формы** — по CLDR: база + `.one` / `.few` / `.many` / `.other`
   (`.zero`/`.two` тоже допустимы). Гейт сравнивает базовые ключи, а лишние
   плюральные суффиксы разрешены только когда у owner есть `<base>.other`.
3. **Счёт без плюральных ключей** — нейтральный: «Агентов: {count}»,
   «Записей: {total}», «Ещё {count}», «Показать ещё строк: {n}». Формы
   «{count} агентов» в таких строках не используются.
4. **Терминология**: `subagent` → «субагент» (не «Subagent», не «подагент»,
   не «Суб-агент»); `turn` → «ход»; `credit` → «кредит»; `teammate` →
   «участник команды»; `surface` (Record status) → «статус записи»;
   `Peer dependency` → «peer-зависимость» (§9).
5. **Пути настроек** цитируются: «Настройки → Общие», «Настройки → Аккаунт»,
   «Настройки → Встроенные плагины», «Настройки → Рынок плагинов → Темы».
6. **Языковые коды** в предпросмотрах документов — реальные коды локали
   (`sidebarExcel.language` = `ru`, онбординг `onboardingArtworkLocale` = `ru`),
   а не `en`/`zh`.
7. **«Оболочка»** в ядровых настройках (`settings.shell.title`) — заголовок
   раздела; в текстах про терминал по-прежнему «shell» (§3): «интеграция с
   shell», «путь к shell».
8. **Ё и типографика**: «учётные», «обновлён», «Завершённые», «прервёт»;
   многоточие — единый символ «…», а не три точки.
9. **`schedule.manager` — это и есть русский пункт главного меню.** Плагин
   расписаний регистрирует два пространства имён: `schedule.catalog` (карточка
   настроек) и `schedule.manager` (сама страница). Пункт «自动化任务» рядом с
   «Новая сессия» берётся из `panel`/`title` = «Автоматизированные задачи»;
   `task` → «задача», `schedule` → «расписание», `run` → «запуск», `next run` →
   «следующий запуск», `frequency` → «частота», `delivery record` → «запись о
   запуске». Обе базы плюральных единиц (`unit.day/hour/minute/second`) имеют
   `.one`/`.few`/`.many`/`.other`, чтобы «через 1 день / 2 дня / 5 дней»
   склонялось.
10. **Осознанное исключение — `chat.message.stepProcess.sharedPrefix`**: в `en`
   значение пустое (это данные ядра: префикса у английских меток нет; в `zh` —
   «已»), а гейт `check:harness:keys` требует непустых переводов. В `ru` стоит
   один пробел `" "`: значение нигде не рендерится, а используется только в
   `startsWith`-сравнении меток, поэтому поведение идентично пустому префиксу
   (ни одна русская метка не начинается с пробела). Менять чекер ради одного
   ключа не стали — инвариант «непустое значение» защищает остальные тысячи
   ключей.
