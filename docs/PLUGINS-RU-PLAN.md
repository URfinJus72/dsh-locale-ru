# Русификация китайских плагинов DSH — анализ и план работ

Дата: 2026-11-06. База: `@absolutemikhail/dsh-locale-ru` v0.1.0 (upstream `AbsoluteMikhail/dsh-locale-ru`, MIT),
профиль `~/.dsh/profiles/web` (DSH 0.2.0-rc.2), локальная модель `ornith-9b` на `127.0.0.1:8080`.

## 1. Что уже есть

- **Русификация ядра**: пакет `@absolutemikhail/dsh-locale-ru` регистрирует язык `ru`
  (`addLanguage({id:'ru', label:'Русский', fallback:'en'})`) и 48 словарей (namespace'ов) для
  встроенного веб-интерфейса: `settings`, `chat`, `conversation`, `sidebar*`, `plan`, `job`,
  `agent-team`, `approval` и т.д. Механизм — клиентский (браузерный) сервис `ctx.locale`.
- **Плагины, которые нужно русифицировать** (все — китайские авторы, у всех уже есть полный
  английский словарь, но нет русского; поэтому сейчас при локали `ru` их UI падает в `en`):
  `@hyzyn/*` (Apache-2.0), `dshmarket` (MIT), `@nanmicoder/dsh-agent-teams` (MIT).
  `@xbzbing/dsh-git-panel` **уже имеет русский словарь** (554 ключа) — его не трогаем.

## 2. Пять поверхностей «китайского» в DSH и что с ними можно сделать

| # | Поверхность | Где живёт | Механизм локализации | Перекрывается плагином? |
|---|---|---|---|---|
| 1 | UI-словари плагина | `client.js` → `ctx.locale.register(ns,'zh',dict)` / `('en',...)` | клиентский `locale` сервис: `ru` → `en` → `common` | **Да**, регистрацией `('ru', dict)` для того же `ns` |
| 2 | Карточки в «Настройки → Плагины» | `package.json.description` + `locale/*.json` пакета | `readPluginMeta` читает `<pkg>/locale/en.json` и соседние `*.json` | **Нет** — файлы должны лежать внутри самого пакета |
| 3 | Схемы инструментов для модели | host-код плагина: `description`, `parameters` | `system-prompt/assemble` — waterfall над `assembly.tools` | **Да** (официальный хук, «returned value is authoritative») |
| 4 | Заметки в system prompt | host-код: секции `plugin:dsh-*` | тот же waterfall над `assembly.sections/contexts` | **Да** |
| 5 | Рантайм-сообщения (ошибки, результаты) | host-код плагина | нет i18n; текст вшит в строки | Частично (динамическая подмена/словарь по фрагментам — рискованно) |

Вывод: пункты 1, 3, 4 делаются **одним форком без форков upstream-плагинов**. Пункт 2 требует
патча установленных пакетов, пункт 5 — отдельный, дорогой и рискованный слой.

## 4. Ключевые технические находки

1. **Один владелец на (ns, locale)**: повторная регистрация пары бросает исключение.
   Наши словари — всегда новый `('ru', …)`, конфликтов нет. Но если будущая версия плагина сама
   добавит `ru`, наш пакет не должен падать: регистрировать внешние namespace'ы **поштучно в try/catch**
   (свои 48 ядровых — по-прежнему строго, одной транзакцией).
2. **Фолбэк `ru → en`**: неполный русский словарь покажет английский, а не сырой ключ. Можно
   выкатывать по частям.
3. **Плюрализация**: в словарях плагинов нет ключей `.one/.few/.many` (есть только в ядре), `{n}`
   подставляется в одну строку. Правило перевода для счётных строк: грамматически нейтральные
   конструкции («Файлов: {n}», «{n} шт.»), иначе получим «1 файлов».
4. **Git-panel**: регистрирует `{zh, en, ja, es, fr, de, ru, pt}` одним вызовом → его ui-`ru` уже занят,
   регистрировать нельзя; в его `ru`-словаре найдено 2 непереведённых китайских значения (мелочь, опционально).
5. **Хук для host-строк существует**: `ctx.on('system-prompt/assemble', async (assembly, ctx2, next) => {…})`,
   слушатели без scope-тега — глобальные; waterfall покрывает `sections`, `contexts`, `tools`, `variables`.
   Это позволяет переписывать `description` инструментов, `parameters` (вложенные описания) и тексты
   секций по их стабильным именам, без правки upstream-плагинов.
6. **Карточки плагинов** (`readPluginMeta`) читают `locale/*.json` **внутри** пакета через его `exports`.
   Поэтому русификация карточек = патч установленных пакетов (скрипт, идемпотентный, с `--check/--revert`)
   либо форки 9 upstream-проектов (нереалистично). В любом случае это отдельная, опциональная фаза.
7. **Лицензии**: `@hyzyn/*` — Apache-2.0 (производный перевод → сохранить attribution/NOTICE, отметить
   изменения), `dshmarket`, `@nanmicoder/*`, `@xbzbing/*` — MIT, upstream локализации — MIT.
8. **Проверено на ornith-9b**: с инструкцией «не рассуждай, только JSON» 8 коротких ключей
   переводятся за ~5 с, JSON валиден, плейсхолдеры сохраняются; без этой инструкции модель уходит
   в `reasoning_content` и не отдаёт контент (нужен `max_tokens` ≥ 4096).

## 5. Варианты упаковки форка

| | Вариант | Плюсы | Минусы |
|---|---|---|---|
| **A (реком.)** | Форк `URfinJus72/dsh-locale-ru`, имя пакета **как у upstream**, внутри — ядро + плагины | drop-in замена: в профиле меняется только источник `github:`; один пакет, один `addLanguage`; легко мержить upstream | нельзя публиковать в npm под чужим scope (ставится через git) |
| B | Форк + переименование в свой scope (`@urfinjus72/…`) | честная атрибуция, можно публиковать | правки профиля (dependency + bundles), нет автоматического мержа upstream по имени |
| C | Отдельный overlay-пакет поверх upstream (`register ru` только для плагинов) | upstream не трогаем, чистый merge | два пакета в профиле; нет `addLanguage` (зависимость от upstream); нельзя расширять ядро |

Рекомендация: **A**, и в README явно: «не ставить одновременно с upstream — обе регистрируют язык `ru`».

## 6. План работ (фазы, артефакты, критерии приёмки)

### Фаза 0. Инфраструктура форка (≈0,5 дня)
- `gh repo fork AbsoluteMikhail/dsh-locale-ru --clone` → рабочая копия в `projects/test-3/dsh-locale-ru`.
- Baseline: `pnpm i && pnpm run build && pnpm test` зелёные (esbuild + node:test).
- Новый скрипт `scripts/plugin-catalogs.mjs`: читает установленные плагины из профиля (путь параметром),
  извлекает словари `zh`/`en` и **снимки** кладёт в `catalogs/plugins/<ns>.json` (en-значения как источник
  истины + zh для смысла). Снимки коммитим — тесты не зависят от локальной установки плагинов.
- Тест `tests/plugins.client.spec.ts`: набор ключей `ru` == набор ключей `en` для каждого плагина.
- CI: обновить workflow (node 22/24, build+test+`npm pack --dry-run`).

### Фаза 1. UI-словари 9 плагинов (2 699 ключей) (≈2 дня)
- `src/client/dictionaries/plugins/<ns>.ts` (9 файлов) + регистрация в `PACKS` с отдельным,
  «терпимым к конфликтам» циклом для внешних namespace'ов.
- Черновик перевода: ornith-9b, батчи по 8–12 ключей, глоссарий в system-промпте, кэш по (ns,key),
  `--resume`, валидация каждого ответа: JSON, паритет ключей, сохранность `{placeholder}`, отсутствие CJK.
- Доводка: 100 % строк длиннее 120 симв. и все счётные строки — основная модель; остальное — выборочный
  ревью-проход (10–20 %) + единый глоссарий.
- Критерий: `pnpm test` зелёный; в браузере на `ru` у 9 плагинов нет английских/китайских строк
  в UI (ручной чеклист по каждому: карточка настроек, панель/сайдбар, диалоги).

### Фаза 2. Host: описания инструментов и параметров (≈1,5 дня)
- `src/host/tools/<plugin>.json`: по инструменту — полное `ru`-описание + карта описаний параметров
  (путь в JSON Schema). Источник — zh/en из host-кода, снимок в `catalogs/host/tools/`.
- Host-половина пакета: `apply(ctx, config)` + глобальный waterfall `system-prompt/assemble`:
  переписывает `assembly.tools` (description + рекурсивно `parameters.*.description`), если включено
  конфигом; любые ошибки — `try/catch`, промпт не ломаем никогда; kill-switch в конфиге.
- Конфиг в `cordis.patch.yml`: `locale-ru: { prompt: 'ru' }`.
- Дрейф-тест: для каждого инструмента из установленных плагинов есть запись в каталоге; хэши zh-строк
  в снимке — предупреждение при расхождении.
- Критерий: в собранном запросе к модели все 49 описаний инструментов — по-русски; снимок
  `dump-config`/сессии подтверждает.

### Фаза 3. Host: секции system prompt (≈0,5–1 день)
- `src/host/prompt/<section>.json` для 8 секций (`plugin:dsh-*`), полный `ru`-текст.
- Тот же waterfall: секции с известным именем заменяются на русский текст (по хэшу оригинала —
  защита от дрейфа: изменился upstream → оставляем оригинал и пишем warning).
- Критерий: в system prompt нет китайских заметок о плагинах.

### Фаза 4. Карточки плагинов — опционально (≈0,5 дня)
- `scripts/patch-plugin-cards.mjs`: добавляет `<pkg>/locale/ru.json` (+ `exports` для `./locale/ru.json`,
  если его нет), `--check/--revert`, идемпотентно; предупреждение «повторить после обновления плагинов».
- Альтернатива: не делать (карточки останутся с китайским описанием из `package.json`).

### Фаза 5. QA, документация, релиз (≈1 день)
- Тесты: паритет ключей, плейсхолдеры, отсутствие CJK в `ru`, отсутствие дублей (ns, locale),
  идемпотентность/`--check`, сборка esbuild, `npm pack --dry-run`, smoke-install в профиль.
- Ручной чеклист: 9 плагинов × (UI, настройки, панель, ответы агента), 48 ядровых namespace'ов — регресс.
- README/README.en + `docs/PLUGINS.md` (как добавить плагин, как обновлять снимки), NOTICE (Apache-2.0
  атрибуция hyzyn-плагинов), CHANGELOG, тег `v0.2.0-plugins`.
- Пуш в форк, оформление PR/README, инструкция установки в профиль.

**Итого:** 5–8 рабочих дней агента; при команде из 3–4 участников — 2–3 дня календарных.

## 7. Распределение моделей

| Работа | Модель | Почему |
|---|---|---|
| Архитектура, host-waterfall, тесты, документация, ревью | `deepseek/deepseek-v4.1-flash-1017` (основная) | нужна точность в коде/семантике, длинные тексты, решения |
| Черновик 2 699 коротких UI-ключей | `local/ornith-9b` батчами | дёшево и достаточно; замер: ~8 ключей/5 с, JSON валиден, плейсхолдеры держит |
| 23 длинных UI-ключа + счётные строки | основная | грамматика/род/число, «1 файлов» недопустимо |
| Описания инструментов и секции промпта | основная (+ выборочно ornith-9b на параметры) | это инструкции для агента: смысловая ошибка дороже |
| Проверки паритета/плейсхолдеров/CJK/дрейфа | **скрипты, без модели** | детерминированно и бесплатно |
| Ревью перевода | основная, по глоссарию + выборка | терминологическая консистентность |

Ограничения ornith-9b (проверено): reasoning-модель, нужен `max_tokens` ≥ 4096 и явное «не рассуждай»;
один слот на llama.cpp — параллелить бессмысленно; качество на длинных абзацах не проверять, только
короткие UI-строки; обязательно валидировать JSON и повторы ключей.

## 8. Риски и меры

| Риск | Мера |
|---|---|
| Будущая версия плагина добавит свой `ru` → исключение при регистрации | поштучный `try/catch` для внешних ns, warning в консоль, остальные словари продолжают работать |
| Установлены и upstream, и форк → `addLanguage` бросает, вся транзакция откатывается | терпимый `addLanguage` (idempotent) + явное предупреждение в README |
| Waterfall ломает сборку промпта при обновлении DSH | всё в `try/catch`, при любой ошибке возвращаем исходный `assembly`; kill-switch в конфиге; тест-смоук |
| Дрейф upstream-строк (плагин обновился) | снимки + хэши, дрейф-тест в CI, политика: не переводим — оставляем оригинал, warning |
| Качество перевода (особенно host-инструкции) | глоссарий, ревью длинных строк, ручной чеклист, «нейтральные» счётные конструкции |
| Промпт-кэш/стабильность промпта | каталоги статичны, без рантайм-LLM-перевода; одинаковый текст между ходами |
| Лимит «один владелец (ns, locale)» в чужих плагинах | не регистрируем `ru` для `gitPanel` (уже занят) |
| Лицензии Apache-2.0 | NOTICE/THIRD_PARTY_NOTICES, отметка «перевод — производная работа», не менять лицензию upstream |
