# Русские каталоги host-плоскости

Здесь лежат переводы того, что агент видит в системном промпте: описания инструментов,
описания их параметров и 8 секций промпта, которые добавляют плагины. Оверлей
(`src/host/index.ts`) подписан на `system-prompt/assemble` и подменяет строки только при
совпадении хэша — то есть перевод применяется ровно к той версии исходной строки, под
которую он написан.

Источник (снимок с установленных плагинов) — `catalogs/host/tools.json` и
`catalogs/host/prompt.json`; снимок пересобирается командой
`node src/host/scripts/extract.mjs`.

## `tools.json`

```json
{
  "tools": {
    "docker_ps": {
      "hash": "<sha1 исходного zh-описания>",
      "ru": "Русское описание инструмента.",
      "paramHashes": {
        "properties.limit.description": "<sha1 исходного zh-описания параметра>"
      },
      "params": {
        "properties.limit.description": "Русское описание параметра."
      }
    }
  }
}
```

Правила:

1. Набор ключей `tools` — ровно 47 инструментов из `catalogs/host/tools.json`
   (`docker_*` 22, `tty_*`/`sftp_*`/`tunnel_list` 18, `loglens_*` 5, `mcp_*` 2).
2. `hash` копируется **дословно** из `catalogs/host/tools.json`; менять его нельзя —
   это единственный признак того, что исходная строка не изменилась.
3. `params[*]` — пути из `catalogs/host/tools.json` (`properties.<имя>.description`,
   `properties.<имя>.items.description`, `properties.<имя>.oneOf.<i>.description`).
   Наборы путей в `params` и `paramHashes` должны совпадать с каталогом.
4. Markdown (`**`, backticks), имена инструментов/параметров/команд/путей и бренды
   (`DSH`, `DeepSeek`, `tmux`, `SSH`, `SFTP`, `xterm`, `Docker`, `JSON`, `HTTP`, `URL`)
   остаются как в исходнике. Плейсхолдеров `{...}` в описаниях инструментов нет, но
   если появятся — сохранять.
5. Перевод — редакторский, а не буквальный: это инструкции агенту, важнее точность
   смысла и предупреждений («только чтение», «нужно подтверждение» и т. п.), чем
   дословность. Сокращать предупреждения нельзя.

## `prompt.json`

Статические секции — по имени и хэшу:

```json
{
  "sections": {
    "plugin:dsh-docker": {
      "hash": "<sha1 исходного текста секции>",
      "ru": "Русский текст секции."
    }
  }
}
```

Динамические секции (`"dynamic": true` в каталоге — текст собирается из живого
состояния на каждом запросе) переводятся **по фрагментам**: `fragments[]` каталога
содержит статические куски текста, каждый со своим хэшем. В `ru/prompt.json` такой
фрагмент — это объект с `zh` (копия из каталога, нужна оверлею для поиска), `hash`
(копия) и `ru`:

```json
{
  "sections": {
    "plugin:dsh-rss-digest": {
      "fragments": [
        { "zh": "# 今日值得读 ·", "hash": "<sha1>", "ru": "# Сегодня стоит прочитать ·" }
      ]
    }
  }
}
```

Оверлей подставляет фрагмент только там, где он встречается в тексте ровно один раз;
фрагменты внутри уже подставленных фрагментов не дублируются (сначала применяются
длинные). Пропущенный фрагмент просто остаётся на языке плагина — это не ошибка, но
и не перевод.

Состав 8 секций (`catalogs/host/prompt.json`):

| секция | вид | перевод |
| --- | --- | --- |
| `plugin:dsh-codegraph` | статическая | `hash` + `ru` |
| `plugin:dsh-codegraph:usage` | динамическая, английский исходник | фрагментов нет — не переводится |
| `plugin:dsh-mcp-config` | статическая | `hash` + `ru` |
| `plugin:dsh-rss-digest` | динамическая | `fragments[]` |
| `plugin:dsh-loglens` | статическая | `hash` + `ru` |
| `plugin:dsh-tty` | статическая | `hash` + `ru` |
| `plugin:dsh-tty:terminals` | динамическая (context, не section) | `fragments[]` |
| `plugin:dsh-docker` | статическая | `hash` + `ru` |

`plugin:dsh-tty:terminals` регистрируется плагином как *context* (`systemPrompt.context`),
поэтому оверлей обходит и `assembly.contexts`, а не только `assembly.sections`.

## Проверка

```sh
node src/host/scripts/extract.mjs --check   # снимок совпадает с установленными плагинами
pnpm run build                              # каталоги вшиваются в lib/index.js
pnpm test                                   # тест оверлея + паритет
```
